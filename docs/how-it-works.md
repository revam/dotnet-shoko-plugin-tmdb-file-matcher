# How it works

A walk through the plugin, in the order a file goes through it:

```
file → evidence → tags → search → score → placement → release → validator
```

Every path below is under `source/`.

## The plugin and its services

`Plugin.cs` is the plugin class. Its identity, `PluginID`, name and overview,
is written in the project file and the class itself is generated by
`Shoko.BuildTools.Targets`; the partial class here only adds
`RegisterServices`, which registers three things:

- `ITmdbCatalog`, the port over core's metadata services;
- `PathParser`, built with the Offline Importer's `IOfflineMatchingService`
  when the importer registered one, and `null` when it did not
  (`GetService`, not `GetRequiredService`);
- `MatchPipeline`, which ties the rest together.

The release provider and the validator are **not** registered. Core finds
them by their types, and keys them by a UUIDv5 of their full names, so
`Shoko.Plugin.TmdbFileMatcher.TmdbReleaseInfoProvider` and
`Shoko.Plugin.TmdbFileMatcher.TmdbCrossReferenceValidator`, like the
settings class `Shoko.Plugin.TmdbFileMatcher.TmdbFileMatcherConfiguration`,
are never renamed or moved.

The dependencies are `PluginDependency` items in
`Shoko.Plugin.TmdbFileMatcher.csproj`: TMDB required, the Offline Importer
`Optional="true"`. `shoko-build` copies them into the manifest's release
entry. The importer's abstractions package is a plain `PackageReference`, so
its assembly ships in the plugin's archive and its types load whether or not
the importer is installed.

## The catalog

`Catalog/TmdbCatalog.cs` is everything the plugin asks core:

- **searches** through `IMetadataLinkingService.SearchSeries` and
  `SearchMovies`, on `MetadataSource.TMDB`;
- **lookups** through `LookupSeries` and `LookupMovie`, which add the alternate
  titles and the regular seasons with their episode counts;
- **what the server stores** through `IMetadataService`;
- **refreshes** through `IMetadataRefreshService.RefreshEntry`, quick, without
  images, and `immediate`, so the call returns once the show is stored.

It is an interface, `ITmdbCatalog`, so the tests run the whole matcher and
the validator over a fake (`tests/Fakes.cs`).

## Evidence

`Evidence/PathParser.cs` reads a path into the importer's own
`ParsedFileResult`: with the importer's rules when it is installed, or with
`ParseBuiltIn` when it is not. The built-in parser reads TMDb tags in any
segment, `SxxEyy` and `SxxEyy-Eyy`, `Name - NN`, a leading `[Group]`, and a
`(Year)` in the file name; anything else is a bare name, as a movie's is.

`Evidence/EvidenceReader.cs` turns the parse into a `FileEvidence`
(`Evidence/FileEvidence.cs`):

- the year split off the series name, or taken from the nearest folder;
- the season from a `Season N` or `Specials` folder when the file names none;
- the series name from the nearest folder when the file gives none, passing
  over folders that only sort a library, such as `Series`, `Anime` or
  `Unrecognized`;
- the series name read straight from the file name, kept when it differs
  from the parser's, because a parser can misread a name;
- whole episode numbers, and whether one is fractional, such as 12.5;
- the TMDb tags in the order they are taken: forced, then the file's, then
  the folders', nearest first;
- whether the file looks like a movie.

A video with several files is read at every location, and the reading that
says most is used.

## Tags

`MatchPipeline.ByTags`, in `Matching/MatchPipeline.cs`, takes the first group
of tags, those from one place in the path:

- **episodes** (`e`) must be stored, after one refresh of the tagged show, and
  belong to it;
- **a show** (`tv`, `s` or `a`) is placed into, as a search hit would be;
- **a movie** (`m`) must be stored or found by a lookup;
- **a bare number** is tried as a show first when the file has an episode
  number, and as a movie first when it does not.

A tag that does not resolve ends the match with nothing. A tag is the user's
word, and a guess past it would overrule them.

## Search and score

`Search/QueryPlan.cs` builds the searches, in order: the name with its year,
the name, the name without a season suffix such as `S2`, `2nd Season` or `II`,
the name without its subtitle, the file name's own reading, and the folder's
name. A stripped suffix also gives a season hint.

`MatchPipeline.BySearch` searches shows or movies, the likelier first, and
each search of the plan in turn, stopping at the first accepted candidate.
The three best hits of a search that lack their seasons, or whose titles do
not match, are looked up for what a search leaves out. Searches and lookups
are kept in memory for an hour, so the files of one folder search TMDb once.

`Search/CandidateScorer.cs` scores each hit out of 100:

| Term | Points |
|---|---|
| Title | 65 exact, 60 for the part before a subtitle, up to 50 by likeness (`Search/TitleFolding.cs`) |
| Year | 20 the same, 12 one apart, 0 two apart, refused further; 8 when either is unknown |
| Fit | 15 when the season holds the episode, or a movie is matched to a movie-shaped file; refused when it cannot hold it |

`Decide` accepts the best at the accept score (80) when it leads the next by
10, takes it provisionally at the provisional score (60), and takes nothing
below.

## Placement

`Matching/SeasonalPlacement.cs` places the file among the show's stored
episodes:

- `SxxEyy`, or a season from a folder or a suffix, as given;
- no season as season 1, or else as absolute numbering across the regular
  seasons in the order they aired;
- `S00` and specials in season 0.

`MatchPipeline.Place` refreshes the show first when it is not stored, or
when the stored episodes do not hold the file. The refresh is bounded to 30
seconds; running over is treated as TMDb being unavailable, which gives no
result and a rescan later.

## The release

`TmdbReleaseInfoProvider.cs` is the `IReleaseInfoProvider`. It builds a
`ReleaseInfo` whose cross-references name TMDb entries, episode then show,
or the movie alone: no AniDB IDs. A provisional match sets `DeferToNext`,
so the next provider in core's chain still gets its turn.

**Manual by default.** `CannotAutoMatchReason` says why core's automatic
searches get nothing: the importer is not installed, or no auto-match rules
are set up. With both, an automatic match is saved only when the importer's
`IOfflineAutoMatchService` allows it under those rules.

**Unavailable is not unmatched.** When TMDb cannot be reached,
`GetRescanDelay` asks core to try again after TMDb's `RetryAfter`, or an
hour.

## The validator

`TmdbCrossReferenceValidator.cs` is the `IReleaseCrossReferenceValidator`
for TMDb's shows, episodes and movies. Core asks it about every
cross-reference naming one of them, whoever wrote it.

- **The entry exists.** A show or a movie not stored is looked up; one TMDb
  says it does not have is refused. One that cannot be checked, TMDb being
  unreachable, is taken as it is.
- **An episode not stored** is taken as it is.
- **An episode without its show** has the show filled in, right after the
  episode.
- **An episode with the wrong show** is refused when saving, and healed when
  healing: the episode's own show takes the wrong one's place.
- **Two shows** in one cross-reference are refused when saving, and left as
  they are when healing.

Only TMDb IDs are ever added or removed, and ranges are never touched. When
healing, nothing is looked up and nothing is refused.

## Settings

`TmdbFileMatcherConfiguration.cs` holds the two scores, whether restricted
entries may match, and the auto-match rules, the importer's own
`AutoMatchRule`. Core draws its settings page from the class, and refuses
at start-up a shape its schema generator cannot draw;
`tests/ConfigurationSchemaRulesTests.cs` mirrors those rules.

## Tests

- `FilenameCorpusTests`: paths, the importer's parse of each, and what they
  link to, with real file names from a test server.
- `BuiltInParserTests`: the same shapes without the importer.
- `ValidatorTests`: every rule, saving and healing.
- `ConfigurationSchemaRulesTests`: core's schema rules.
- `CompositionTests`: the provider and the validator built as core builds
  them, with the importer absent and present.
